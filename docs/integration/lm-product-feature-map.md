# LINE 功能放哪、怎麼串接(LM × 產品對照表)

- 依據：`adr-001-lm-product-boundary.md`(分工)、`bridge-v1.1-draft.md`(`lm:`／`px:` postback、事件轉發、LINE 身分換 ref)
- 對象：設計 Rich Menu、Flex、Imagemap、關鍵字回覆的人(攝影師／設計師／Tim)
- 2026-11-24。標「v1.1」的項目**還沒實作**，現在設定了也不會動作。
- LINE 各種訊息與動作的限制(數量、字數、支援哪些動作)以 LINE 官方文件為準，本文只寫和分工有關的部分。

---

## 1. 三個問題決定放哪

1. **需要知道「這位客人是誰、他的案子」嗎？** 需要 → 內容由產品(IP)回答。
2. **內容由誰維護？** 會隨業務改變的內容(方案、價目、作品集、進度)→ IP；固定的 LINE 互動(營業時間、聯絡方式、選單版面)→ LM。
3. **在聊天室回答，還是開網頁？** 圖片多、內容長 → 開網頁(網址按鈕)；一兩句話 → 在聊天室回。

---

## 2. 「按下去會發生什麼」：所有按鈕共用的 6 種接法

Rich Menu 的區塊、Flex 的按鈕、Quick Reply 的按鈕、Imagemap 的區塊……**每一個可以按的地方，都是從下面這幾種接法裡挑一種**。設計時只要決定每個按鈕用哪一種。

| # | 接法 | 填什麼 | 結果 | 誰處理 | 現況 |
|---|---|---|---|---|---|
| ① | **網址(URI)→ IP 公開頁** | `https://imhoti.tw/studio/…`(作品集、方案頁) | 在 LINE 內建瀏覽器開 IP 的網頁 | IP | ✅ 現在可用 |
| ② | **網址(URI)→ 客人專屬頁** | `https://liff.line.me/<LIFF ID>/bridge/identity?p=ip&to=/我的相片路徑`(LIFF ID 由 LM 自動建立) | LM 先確認是哪位客人，再帶到 IP 的客人頁 | LM 驗身分 → IP | ⏳ v1.1 C |
| ③ | **傳文字(message)** | 一段文字，例如 `營業時間` | 等於客人自己打字 → 觸發 LM 的關鍵字回覆 | LM | ✅ 現在可用 |
| ④ | **postback `lm:`** | `lm:reply?key=hours`(回關鍵字回覆 `hours` 的內容)、`lm:menu?tab=wedding`(切換選單分頁) | LM 回固定內容；聊天室裡**不會**出現客人「說了一句話」 | LM | ⏳ v1.1 A |
| ⑤ | **postback `px:ip:`** | `px:ip:plans`、`px:ip:status` | LM 轉給 IP，IP 在 2.5 秒內回答；逾時就回備用的網址按鈕 | IP 回答，LM 送出 | ⏳ v1.1 B |
| ⑥ | **LINE 內建動作** | 切換 Rich Menu 分頁(richmenuswitch)、選日期時間、開相機或相簿、傳位置、複製文字 | 由 LINE 處理，或產生對應的事件 | 看用途(見 §4) | 依 LINE 支援 |

**③ 和 ④ 怎麼選**：③ 會在聊天室留下客人「說了」那句話，客人看得懂，現在就能用；④ 比較乾淨，但要等 v1.1 A。**現在先用 ③，v1.1 A 上線後再視需要改成 ④。**

**還沒上線前的替代做法**：需要 IP 資料的按鈕(⑤)，先用 ① 開 IP 的網頁代替。

## 3. 各種 LINE 功能：放哪、誰設定、按鈕怎麼接

| LINE 功能 | 放哪 | 在哪設定 | 內容來源 | 按鈕可用的接法 | 備註 |
|---|---|---|---|---|---|
| **Rich Menu(含分頁)** | **LM** | LM 後台(`richmenu`、`segmented_richmenu`) | 圖片與版面：LM | ①②③④⑤⑥ | 版面和分頁是 OA 的設定，所有好友看到的都一樣；「誰看到哪一版」也在 LM |
| **歡迎訊息**(加好友時) | **LM** | LM 後台(welcome) | LM | 訊息內的按鈕：①③④⑤ | 可以附 Quick Reply；可以順便引導客人「傳綁定碼」 |
| **關鍵字回覆** | **LM** | LM 後台(`keyword_reply`) | 固定內容：LM | 回覆內的按鈕：①②③④⑤ | **要查 IP 資料時**：關鍵字先回一個帶按鈕的訊息，按鈕用 ⑤(例如關鍵字「進度」→ 回「點這裡查進度」＋按鈕 `px:ip:status`)。這樣不必修改契約 |
| **Quick Reply**(訊息下方的小按鈕) | **LM** | LM 後台(`quick_reply`)，附在 LM 的回覆上 | LM | ①③④⑤⑥(開相機、相簿、傳位置等只有 Quick Reply 有) | IP 的通知(`/messages`)目前**不能**附 Quick Reply |
| **Flex Message — 固定內容**(價目卡、服務介紹卡) | **LM** | LM 後台(`flex`)，用在關鍵字回覆、歡迎訊息、Rich Menu 的回覆 | LM | ①②③④⑤ | 內容很少變動才放這裡；會常改的價目，建議改用 ⑤ 讓 IP 回答，或用 ① 開網頁 |
| **Flex Message — IP 的通知**(交件、問候、群發) | **IP 決定內容** | IP 送出(`POST /messages`)，外觀由 LM 統一的範本決定 | 標題、內文、一顆按鈕：IP | 只有一顆按鈕，必須是 ①(網址在登記的網域內) | IP **不能**自訂 Flex 版面；要改外觀，就改 LM 的範本(所有通知都會一起改) |
| **Flex Message — IP 的即時回答**(postback ⑤ 的回覆) | **IP 決定內容** | IP 回覆 LM 的事件轉發 | IP | 一顆按鈕，① | 格式同上(v1.1 B) |
| **Imagemap**(整張圖切成可點區塊) | **LM** | LM 後台(`imagemap`) | 圖片：LM | **只能用 ① 和 ③**(LINE 的 Imagemap 不支援 postback) | 要查 IP 資料時：區塊用 ③ 傳文字 → 觸發關鍵字 → 關鍵字回覆帶 ⑤ 按鈕；或直接用 ① 開網頁 |
| **一般訊息**(文字、圖片、影片、貼圖、位置) | **LM** | 關鍵字回覆或歡迎訊息的內容 | LM | — | |
| **對話流程**(`flow`) | **LM** | LM 後台 | LM | 依流程設定 | 只做固定的互動流程；不要在流程裡存客人資料 |
| **LIFF 頁面** | 身分頁在 **LM**；IP 的頁面是一般網頁 | LIFF 由 LM 自動建立(v1.1 C) | — | ② | IP 不必自己做 LIFF |
| **對所有好友群發／分眾推播** | **LM** 或 LINE 官方帳號管理 App | LM `push_message` | LM | ①③④ | LINE 本身的群發，不需要客人資料 |
| **依專案條件挑客人群發** | **IP** | IP(`docs/client-broadcast.md`，尚未實作) | IP | ① | 經 `/messages` 一則一則送 |
| **交件通知、紀念日問候** | **IP** | IP | IP | ① | ✅ 交件通知已上線；問候的後端已完成 |
| **LM 的會員、標籤、等級**(`member`、`tag`、`tier`) | **LM** | LM 後台 | LM | — | 只用來決定 LM 自己的選單與回覆給誰看，**不是客人 CRM**，不和 IP 同步 |
| **客人傳來的圖片、貼圖、位置** | — | — | — | — | LM 目前不處理非文字訊息；要回覆時，用 LINE 官方帳號管理 App 手動聊天 |
| **和客人手動 1 對 1 聊天** | LINE 官方帳號管理 App | — | — | — | 不在 LM 也不在 IP |
| **優惠券、集點卡、LINE VOOM** | LINE 官方帳號管理 App | — | — | 可以用 ① 連過去 | 不在 LM 也不在 IP |

## 4. LINE 內建動作(⑥)的用途

| 動作 | 用在哪 | 結果 | 建議 |
|---|---|---|---|
| 切換 Rich Menu 分頁(richmenuswitch) | Rich Menu | LINE 直接切換，並送出一個 postback 事件 | 分頁切換用它；LM 不必回覆 |
| 選日期時間(datetimepicker) | Rich Menu、Quick Reply、Flex | 送出 postback 事件，附上選好的日期 | 預約功能在 IP 的「不做」清單上；有需要時，用 `px:ip:` 前綴讓 IP 處理 |
| 開相機、相簿、傳位置 | **只有 Quick Reply** | 客人傳圖片或位置給 OA | LM 目前不處理圖片和位置訊息；先不用 |
| 複製文字(clipboard) | 依 LINE 支援的位置 | 把一段文字複製到客人的剪貼簿 | 適合匯款帳號、綁定碼；放在 LM 的固定回覆 |

## 5. 設計師的串接步驟

1. **先列出所有按鈕**：Rich Menu 每一格、Flex 卡片的每顆按鈕、Quick Reply 每一顆。
2. **每顆按鈕依 §1 的三個問題，從 §2 挑一種接法**。不確定時，先用 ① 開網頁，最穩定。
3. **命名規則**
   - `lm:reply?key=<關鍵字代號>`：代號和 LM 關鍵字回覆裡設定的一致。
   - `px:ip:<動作>`：動作名稱用英文小寫，例如 `plans`、`status`、`portfolio`；新增動作要先告訴 IP 那邊。
   - postback 的 data 最多 300 字元。
4. **每一個 `px:ip:` 按鈕都要設定備用內容**：一句話加上一個網址按鈕，在 LM 後台設定。IP 來不及回答時，客人會看到這個。
5. **網址只能用 IP 登記過的網域**(目前是 `imhoti.tw`)。按鈕裡不要放客人姓名、專案 id 或選片 token(Rich Menu 是所有人共用的)。
6. **測試**：用測試用的 LINE 帳號逐一按過每顆按鈕。需要客人資料的按鈕，要分別用「已綁定」和「未綁定」的帳號各測一次。

## 6. 什麼時候能用

| 接法 | 狀態 | 需要什麼 |
|---|---|---|
| ① 網址 → IP 公開頁 | ✅ 現在 | IP 要有對應的公開頁面(例如作品集、方案頁；作品集網站見 IP backlog 的未來構想 C) |
| ③ 傳文字 → 關鍵字 | ✅ 現在 | — |
| ⑥ LINE 內建動作 | ✅ 依 LINE 支援 | — |
| ④ `lm:` postback | ⏳ v1.1 A | LM 開發(範圍小)；同時拿掉現在那句「已收到您的操作」 |
| ⑤ `px:ip:` postback | ⏳ v1.1 B | LM 與 IP 都要開發，並做安全審查 |
| ② 客人專屬頁 | ⏳ v1.1 C | LM 與 IP 都要開發；攝影師要先建一個 LINE Login channel |
